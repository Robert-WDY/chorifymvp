## 主要结论

“分镜图没出来”首次发生在准备阶段：没有调用任何图片生成、编辑或提交工具。不是供应商图片接口报错、图片参数错误或媒体生成失败。该轮为12次主模型调用、15条工具选择记录，其中7条因单工具约束未执行，8条成功读取；最后记录为cancelled（This operation was aborted）。没有模型网络错误；Trace不能单独证明取消来自哪次按钮操作。

### 1. 摘要被一个过大的历史读取组阻塞

- 第3轮读“提示词改写”得到7153字符正文。整组原始调用与结果估算为9231 tokens，尚未加摘要system、前一份摘要及数据封装。
- 摘要输入上限为8000。现有实现从最早未覆盖的位置逐组装入；第一组超限就break，不能越过去；没有处理这种大组的有来源压缩表示。
- 三份摘要只推进到记录28，停在该Skill之前。最新摘要仍长篇复述早期模型介绍及工具清单，尚未覆盖后来的自行车创作。
- 离线对完整快照运行现有maintainMemory：返回calls=0、respond回调0次、覆盖范围仍28。不是摘要模型调用失败，而是构造输入阶段根本没进入摘要模型。
- 根因在历史工具结果粒度与摘要输入上限的衔接，不是简单“没有记忆”或“多给一点提示词”。不应靠删除原文或把覆盖位置越过未处理内容来消除现象。

程序优先保证最新用户消息、最新结果和显式ID，再按倒序尝试装入完整组；不会把当前任务的一组已读方法作为稳定资料集合保留。24000预算中，6500预留、7207工具定义估算，实际输入可用约10293；最后多步都接近这个上限。旧摘要、工具定义、来源索引及错误记录共同占用空间。

模型三次成功读取同一输出模板；决定重读前，相应模板正文确实已不在输入中。重复读取不是纯粹“看见还忘了”；但为何不利用已有信息开始准备、仍不断选择更多参考，是Agent决策责任，单次Trace不能量化模型能力和噪声各占多少。

### 3. 多工具选择与单步执行限制不一致

本轮三组同时选择3、2、2个工具，7条全部被single_tool_call_required拒绝；不是7次工具内部执行失败。供应商协议开关仍为关闭，适配器没有发送parallel_tool_calls:false，系统仅用文字要求一次一个。拒绝忠实执行现有规则，但浪费主模型步骤，并让失败记录进入窗口、挤出成功资料。

应先在受控预算下验证供应商对协议参数的支持，再同步限制；不能直接开放并行副作用或把执行器改成偷偷串行来掩盖模型选择与真实执行不一致。本轮未调用供应商验证参数。

### 4. 被裁Skill索引没有准确区分成功与未执行

omittedSkillReads从所有read_skill调用建索引，没有检查结果ok或status；同一slug/reference最后一条覆盖前一条。被整组拒绝的调用也可能成为对应资料的回读入口，回读得到的是未执行错误，不是方法正文。

这不是ID不存在：ID确实能读到记录，但记录的内容类别不符合“找回方法资料”的用途。根因是调用记录身份与成功资料身份混用。应分别保留最近成功结果与最近失败状态，不能用失败记录替换可读正文来源。本轮仅定位，没有修改此逻辑。

### 5. 在原话仍可见时，后续意图仍被旧任务吸引

中间几轮用户要求整理、按视频要求生成提示词，回复多次返回原来的风险改写和“下一步我可以……”；场景从非机动车道改到沿江道路、再变成城市主干道的封闭赛道，没有明确说明是在做哪一版的哪些改动。已有新版本没有稳定成为下一步使用对象。

“整理”和复制助手建议的那轮原话本身存在歧义，不能断言模型已经知道具体时长/比例。问题在于既没有针对必要缺口提问，也没有声明假设后完成对应格式，而是继续旧的改写任务。不能归因于来源文件失效：这段没有引用文件，也没有生产工具失败；属于会话承接、版本选择及任务推进的语义问题。

问底层模型时，服务端知道deepseek-flash，但该信息未进入首次Agent输入；它称无法确定型号。这是具体的运行信息缺口，不是模型故意无视已收到的型号。工具能力回答基本符合当前注册表及模拟模式，没有证据表明此次把Skill当作真实视觉能力。

## 建议的修复顺序与验收

1. **先修资料可持续读取**：大工具结果为摘要提供有来源的有界表示；保留持久原文和回读位置；证明覆盖能通过大组、不会伪称已覆盖未处理内容。为当前任务已读取的必要方法提供稳定、去重的模型视图，勿只加ID而裁掉不可缺正文。
2. **修索引的结果身份**：成功读取、失败未执行分开记录；用“先成功、再同参数失败”的离线案例证明成功正文入口不被覆盖。
3. **再验收决策**：同一组8轮原话创建独立会话复测，逐步看最新稿是否存在、配套资料是否存在、是否转入准备方案，而非只看HTTP200；方案数量/格数和实际内容人工核对。
4. **协议与真实媒体分开验收**：受控探测单工具参数；真实图片需先保存明确方案并批准。此轮没有任何媒体方案，不能把视觉/生成质量算已测，也不能将模拟产物视为真实交付。

不建议先加总审查Agent、硬写分镜调度或只扩大上下文预算；这些不能消除大组阻塞和失败来源覆盖，反而可能延长循环。本轮后端问题均为已定位、未修复。Enter修复和这些问题没有因果关系。
