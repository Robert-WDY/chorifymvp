## 输入和工具变化

`context-before.json` 和 `context-after.json` 是同一会话的离线请求投影，含 system、完整消息、工具 Schema 和预算。两边 omittedRecords=0、长稿全文均在，原消息身份从8到14，早期原稿ID从缺失到可用。不是实际模型 A/B。

局部修改给准确父版本和 `edits:[{before,after}]`，每项位置均基于同一原稿解析再应用，不猜同义词或全局替换。禁止歧义命中、重叠、找不到原文、净结果未变及过期版本。未触及内容逐字保留。完整重写入口仍可用，模型仍负责何时选择该入口。

`read_asset/read_history/read_approval` 的 forRevision 在原稿旁提供当前轮真实用户原话，排除助手误述。分页及裁剪标记保留；历史原文、周围记录和修改指令共享返回预算。完整原稿已可见时不强制再读。

媒体沿用原准备工具和 replacesProposalId，只传修改片段或改变参数。图片生成方案改 prompt，图片编辑方案改 instruction；其他参数、视觉来源、文字来源继承。合成参数再通过原先完整 Schema，新方案不继承旧批准。准备持久化失败时回滚新方案，不让原方案失效。

文稿回执差异是首尾公共部分以外的实际包围区间，不是逐处最小 diff 或语义审查。媒体回执列出改变字段。模型视图保留差异摘要与回读入口，完整正文、原始回执、哈希留在存储。公开卡取实际资产正文，不取模型重述。

## 尚未解决与真实验收

程序保证选中原稿上的声明片段准确应用，不能保证模型选中了用户想要的原稿或最小语义范围。模型仍可能选择过大before、绕走全文入口、漏掉要求或最终错述。离线反例明确保留“实际18元、回答20元”；保存卡解决真实版本展示，并未独立阻止普通回复的谎报。

真实验收须另核对模型和预算，使用自然表达及每组新会话：

1. 并列长短稿、指定较早版本、长历史和当前纠正；审查真实输入、所选父ID、原始片段、保存版本关系，不只看标题。
2. 修改价格、删一句、换背景、换尺寸，穿插明确保持及未知项；审查是否自主选择增量操作、是否只改授权范围。
3. 将用户原话、保存正文、回执和最终回复逐项对照；无变化、错来源反馈后检查真实恢复，不用completed评分。
4. 真实媒体单独批准具体新方案；先核对继承参数，再生成/编辑，最后源图与成品双图观察。提示词保留瓶型不证明实际画面保留瓶型。
