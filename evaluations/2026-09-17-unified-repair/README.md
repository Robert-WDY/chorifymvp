## 性能与存储限制

长会话测量是单次本机合成样本：1000 资产、200 份长参数方案、1000 条消息，分别记录初存、上下文组装、追加、恢复的毫秒及 RSS/heap 前后快照。具体数值以 performance.json 为准。增量有效载荷很小仍需要检查历史与对象；恢复仍加载常规原文与资产。这里没有峰值采样、并发压测或生产容量承诺，payloadBytesWritten 不等于总磁盘写入量。

## 回滚与恢复

1. 停止会话写入，保留整个最新数据目录及当前代码提交。不要只使用旧 JSON 迁移备份。
2. 在当前版本运行 `node evals/context-agent-export.mjs <data-directory> <owner> <session-id> <new-full.json> <new-baseline.json>`。输出只能新建，不能覆盖；完整副本包含全部原文、资产、批准、回执、摘要及系统观察。
3. 基线 a4220e1 只能导入兼容副本到**新的**数据目录：文件放入 `<new-directory>/<sha256(owner)>/<session-id>.json`，用基线 HistoryStore.load 迁移。不要让旧代码打开新 SQLite。系统观察在兼容副本中成为保留原输出的运行证据，摘要单独保留在完整副本；旧 Agent 不具备新语义。
4. 恢复本批版本时，同样将完整副本导入另一新目录，核对原文、资产、批准、回执、摘要和系统观察再切换。回滚期间产生的新记录必须另外保全，不能用早期副本覆盖它们。

上述当前/基线导入已经对摘要样本和按钮执行样本实际运行，并逐对象比较完全相等。真实用户会话迁移未运行。旧真实方案缺少冻结供应商配置时，需要重新准备并展示，不静默按新配置执行。巨大不可分历史组无法容纳于摘要输入时仍可按 ID 回读；不保证所有极端超长当前请求均能进入模型。

本批代码及 Schema 的内容指纹见 manifest.json；最终提交 SHA 由包含本目录的 Git 提交确定，避免把基线 SHA 写成新代码 SHA。没有上传 `.env`、凭据、真实运行数据库或私人用户数据。
