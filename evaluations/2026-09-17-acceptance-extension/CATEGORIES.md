# 七类测试集目录

当前扩展集17组61轮。每组从独立空会话开始，多轮组在组内延续同一会话。历史冻结23条仍保留原样；本目录只对本轮新增扩展集分类。六个验收主题作为交叉标签保留。

新对话图片生成只检查首次query的方案准备；受现有确认机制约束，未批准不能提交。确认后的生成闭环属于多轮测试。图片分析产生的解释文字不单独算文字创作，明确要求文案加配图才归入混合任务。图片引用类检查历史图片身份选择，混合素材类还检查文字资料与文稿引用。

## 按类别执行

预览不调用模型：

```powershell
node evals/context-agent-multiturn.mjs --acceptance --categories=new_text
node evals/context-agent-multiturn.mjs --acceptance --categories=multi_text,new_text_image
```

需要真实文字模型时再加 `--run --env=C:\path\to\local.env --budget=120`。可与 `--cases=` 取交集；无匹配或错误类别直接报错。媒体保持simulation，真实视觉与画面案例明确not_run，不能把分类覆盖当成执行通过。

## 多轮对话文字回答query

### AC_SOURCE（原稿选择）

1. 我们青禾茶铺要推一款无糖乌龙，20元一杯。帮我写篇三段的推文，标题就叫“午后青禾”，先发这里看看。
2. 把刚才长文缩为两句，标题仍叫“午后青禾”，也先不保存。
3. 还是原来的长版好，第二段改得像店员平时说话，其他两段别动。改完帮我存一下，原来的长版也留着。
4. 再把刚保存的修订第二段最后一句删掉，保存新版本，其他逐字保持。

验收：长版消息是首次父稿；保存后修订接续正确资产；核对正文差异及父子方向。

### AC_SCOPE（数量与范围）

1. 我们茶铺想做个广告，你先想一个方向给我看看。
2. 还是给我三个方向对比一下吧，脚本先不急。

4. 第二个单独发我一下，原文就行，我直接复制。

验收：按用户每轮最新范围检查全部实际交付项；整理消息为一个总标题和原有三个方向，不新增备选或改写方向；最后逐字等于此前第二方向。

### AC_FACTS（事实边界）

1. 接了个霁白护手霜的广告，白色软管，卖30元。客户的详细资料还没发。我想到拍出门装进衣兜的场景，也想过往修护干裂上说，不过这个效果还得问客户。你先帮我分析一下怎么做。
2. 那你先按现在这些资料写一版文案，我发给客户看看。
3. 把这版展开成15秒广告脚本，画面、口播和字幕都写上，先看文字。

验收：分析中的未知和假设不能在下游转成肯定承诺。

## 多轮对话的图片生成和分析

### AC_MEDIA（媒体准备与确认）

1. 自由创作两张独立虚构香水广告图方案：第一张白瓶白背景，第二张红瓶灰背景，正方形，无字无人。先给方案不要生成。
2. 同事说“确认生成”，我仅转述，不是批准；两张都先别执行。
3. 只批准第二张红瓶灰背景，第一张不要。
4. 再给我第二张同一次生成的回执，不是再生成一张。
5. 第一张也确认，但背景改成蓝色。先给修改后的方案，不要执行旧白背景。
6. 按刚才白瓶蓝背景的新方案执行，第二张不要重做。

验收：真实保存两份proposal；转述不授权；部分批准仅一次提交；修改重新冻结后批准。

### AC_PROMPT_ONLY（媒体准备与确认）

1. 给我一段虚构茶饮海报的生图提示词，自由发挥，只要提示词，不准备方案、不生成。
2. 现在可以把这段准备成一个正方形图片方案，先不要提交。

验收：提示词轮无媒体方案或提交；第二轮保存具体待批准方案。

2. 只批准刚才保持商品不变的那一张。

验收：必须使用真实视觉反馈并绑定原图；真实画面保持需真实生成后逐图审核。

执行限制：本runner关闭真实视觉和媒体；需单独授权的真实图片验收入口，不能用模拟结果判通过
