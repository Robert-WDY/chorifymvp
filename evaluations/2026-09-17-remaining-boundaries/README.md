## 已复现并修复

### 1. 重测可以覆盖已有要求

旧处理只看最新一份有 requirements 的测量回执。同一轮先按四字下限判定失败，再改成一字下限重测，原不合格正文就能完成；删除数量字段、改计数口径、把标题算进正文也有同类边界。根因是检查结果绑定了稿件，却没有持续消费此前已有效声明的要求。

现在测量从本轮已有的真实调用与回执恢复声明，对最终完整回复共同检查。字数按计数口径和正文/全文范围合并为至多四组，数量保留有效声明；重测修改正文，不通过降低下限、提高上限或遗漏字段让原稿转绿。`effectiveChecks` 返回实际生效口径和数值，最终回复门禁继续使用同一测量结果，不另做第二份判定。没有新持久状态，重启读取原回执即可恢复。

普通无 requirements 的临时测量不声明最终要求；参数非法或工具失败不建立新有效声明。用户下一轮改变要求时重新识别，不把上一轮范围冻结到以后。尚未解决的最终测量错误仍不能被无约束测量掩盖。

**副作用/边界**：requirements 只适用于本轮完整最终回复；临时片段使用普通测量。有效声明彼此冲突时无法通过，需由 Agent 说明冲突/澄清，而不能悄悄删掉较严格条件。如果 Agent 自己误声明了有效但过严的条件，可能增加一次澄清；程序仍不能证明声明准确表达用户意图。未识别要求、把多个语义成果塞进一个 item 的问题仍需真实模型验收，未新建关键词解析器处理。

### 2. 原消息格式在归档与修订之间不一致

旧存档入口支持字符串和全为文字的内容数组，修订入口只支持字符串；合法原文能存档但直接修订报不存在。原稿索引又把数组的序列化 JSON 当成长度与片段，使实际正文身份不一致。

现在索引、归档、修订共用原文读取：字符串原样保留；完整文字数组按原顺序以换行连接。来源范围始终是该规范化文字的 UTF-16 范围，实际消息及其分段结构不修改。相同正文可复用已归档父稿，版本关系继续原子保存。含图片等非文字部分或非法部分的消息明确返回文字原稿错误，不静默剥离内容，也不错误声称消息不存在。

**边界**：混合媒体消息没有自动提取文字作为完整作品，需要 Agent 选择已有准确文字来源。文字数组的分段间使用一个换行，索引、范围与两条保存路径口径相同；非文字输入的错误类型更准确，未放宽来源要求。
