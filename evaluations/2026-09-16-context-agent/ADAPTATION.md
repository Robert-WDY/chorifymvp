# 23 条原始用例适配边界

`fixture/cases` 原样保存本次输入到 State 证据所列的 23 条非视频用例。`fixture/manifest.json` 记录每个原始文件的 SHA-256 和原业务 expected 的独立摘要。输入 JSON、提示词和两张参考图保留，产品资料中的图片引用也纳入输入集合。VIDEO_001、VIDEO_002 不在用户提供的 23 条运行里，本轮不把它们凑入分母。

原始查询、setup_turns、expected、review_criteria 均不重写；既不删除失败用例，也不通过 skip 改写结果。`node evals/context-agent-evaluate.mjs` 默认只验证固定语料完整性并输出 23 条 `not_run`，不请求模型、不加载 `.env`、不生成媒体。

| 原语料机制 | 新入口适配 | 原业务要求怎样保留 |
| --- | --- | --- |
| 每条 case 的会话 | 每条建立全新 createSession | 不继承其他 case 上下文 |
| setup_turns | 依原顺序真正调用同一 Agent | 不预造模型应写的文案、方向或状态 |
| required_inputs | 原文作为文字资产，固定图片通过明确 URL 映射输入 | 不把图片文件路径假冒已观察内容 |
| confirm_batch API action | 只批准 from_round 当时展示的具体 proposal，再将同一 user 原话传入 Agent | 不用“确认”字符串代替服务端批准；不批准后来新增方案 |
| 旧工具名称 | 参考原 tool_policy 解释等价真实调用 | edit_image 必须仍有真实来源和父版本；工具改名不算完成 |
| 旧 task 状态 | 记录消息、真实工具调用/结果、产物、批准 | 不给新 Agent 伪造 taskStore，不用 completed 状态判业务通过 |
| 媒体结果 | 默认 simulation，显著标记 simulated | 无真实图像时视觉一致性 `not_run`，不能记通过 |
| wait_for_media | 模型可按实际回执决定查询 | 驱动不替模型规划，也不将等待转换成成功 |

## 证据等级

- 语料完整性：哈希证明输入和原 expected 未改变。
- 脚本化模型测试：只证明工具调用协议、实际反馈回传、历史读取及工具层保护能够工作。脚本模型的预设答案不是理解能力证据。
- 真实模型：本轮 `not_run`。必须另核对授权、具体模型和总调用预算。
- 真实媒体与视觉审核：本轮 `not_run`。不通过模拟资源、HTTP 200 或参数正确声称视觉通过。

实际接入的工具反馈可能使同一 query 走不同轨迹。测试约束来源、批准和成品证据等必要关系，不规定无关工具的唯一成功顺序。编辑第三轮如产生新方案，驱动不会偷加用户批准；此时结果如实保留为待批准，原 expected 不做调整。
