# 2026-09-17 Debug 改为问题与处理链

基线2625acd。入口仍为 http://127.0.0.1:3217/debug ，没有建立新产品或迁移会话。上一版以记录和JSON为中心，本轮按用户要求改为“问题 → 模块状态 → 决策/处理/反馈/回复”。

## 用户查看方式

1. 左侧按对话内容选择会话与轮次。
2. 顶部先读本轮要求、错误/待处理项与待核查信号。点击问题能跳到发生处，若存在后续Agent决策则可继续跳转。
3. 查看六个模块最近状态：上下文与记忆、Agent决策、系统处理、工具处理、结果反馈、回复与结束。
4. 沿处理链查看：实际输入组装 → Agent第几次决策及选择 → 系统处理 → 调用返回/系统拒绝 → 下一次输入是否包含反馈 → 后续工具/公开回复。
5. 详情用可读表格、原文、工具参数与命名来源。技术ID、sourceHash、原始JSON进入默认折叠的“原始证据”。阅读视图将标识转换为名称，不更改原始输入输出。

## 显示依据与边界

- 已确认记录：来源/类型/版本/参数等已知门禁错误、工具失败、未执行、未知结果、模型错误、摘要失败、交付检查反馈、运行异常结束。
- 待核查信号：历史裁剪、相同参数再次调用、请求没有返回。裁剪和重复可能合理，不直接断言根因或语义错误。
- 门禁错误按原工具的明确错误码区分“系统拒绝”；其他异常显示“调用失败”，不猜测是模型、网络还是供应商的问题。
- 下一次决策是否收到失败反馈，按下一次真实输入的function_call_output.call_id或系统观察rawResultRef核对。单纯在正文提到ID不算送达。摘要可能承载同一信息，但没有直接证据时只显示“未找到直接反馈，需要核查”。
- 送达不等于理解；后续工具成功不等于用户任务修好。不新增模型审查或语义评分。
- summary_attempt显示实际记录范围及涉及的用户原话，并对照持久摘要和失败记录显示已保存/失败/尚未确认，不将“开始”当“完成”。
- Agent公开文字是实际返回；不补写隐藏推理。模型适配器输入与供应商HTTP完整报文的区别继续保留。
- 旧格式历史没有对应字段时不伪造处理链，原始导出仍可查。
