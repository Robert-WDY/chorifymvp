# 单 Agent 记忆与工具边界修复

本轮按“记忆和用户需求 → Agent 自主规划 → 选择工具 → 执行 → Agent 判断结果 → 回复”实施。基线为 `35547a22c2a0e0b9bb83dfbaac50476bae000b49`，分支 `feat/context-agent-20260916`。代码在 `server/context-agent/`。

`loop.mjs`、媒体批准与幂等门禁 `io-guard.mjs`、HTTP 入口、旧 compiled 执行系统和共享 Skill 原文件均未修改。没有新增 Agent、Planner、业务状态机、逐轮摘要模型或统一语义审核。计划、澄清、工具选择、结果判断仍由现有 Agent 负责。

## 分项改动及独立验收

| 项目 | 实现 | 离线验收 | 仍由 Agent 判断 |
|---|---|---|---|
| 记忆检索 | 排除 search/read 自身回声；邻近原文不夹带 model_request/response；准确 ID 可回读全部历史 | 原话与原始观察保留，持久记录不变，准确 ID 可查 Trace | 选择正确历史、读完相关原文 |
| 方法与能力 | context-agent 专用 Skill 目录投影与方法适配；能力列表来自实际注册工具；模拟模式明确标注 | 固定备选数量消失，旧 compiled Skill 不变，无视频工具时不宣告视频观察能力 | 不将方法目录当作能力；按用户数量交付 |
| 原稿与修订 | 给保留的聊天原文提供可寻址 ID；save_document 可用 sourceMessageId 原样存档，再以 parentId 保存修订 | 原稿不被改写，真实父版本、来源、幂等、保存失败回滚与非法引用拦截通过 | 是否属于作品、修改哪份、何时保存 |
| 观察输入 | 补入来源链文字与同次上传候选资料；候选关系不等于事实归属；观察已有修订图时补入其真实父图 | 原文与未知项真实传入，排除其他会话/无关联文档；同次上传标为候选；双图真实进入观察请求 | 资料对应哪个商品，观察是否可靠 |
| 结果与恢复 | 保留原图/成品身份对；类型错误提示明确正确参数位置；重写 Agent 与观察说明 | 错误重试仍能收到双图，不能把证据传入自动当成验收通过 | 数量、范围、差异、事实边界是否满足；是否继续修复或如实报告 |

## Prompt 条款对照

| 原来的输入或条款 | 现在的输入或条款 |
|---|---|
| System 要一个，但每轮目录写“推荐＋2–3 备选” | 目录与方法均按用户总数；推荐从总数内选择 |
| 商品原图保持规则容易覆盖所有自由创作 | 明确区分自由设计、真实商品保持、商品事实宣称；普通偏好不作为全部方案阻塞条件 |
| 只有“修改时保存 parentId”，聊天原稿没有便捷资产化入口 | 新稿先保存；聊天原稿可按 messageId 原样存档，收到资产 ID 后修订 |
| 泛化的“区分事实与推断” | 观察结论就地标明不确定性；外观不证明结构、真实尺寸、功能；下游不能升级身份 |
| “对照原图和结果”，重试可能只看成品 | 工具按父版本补入真实原图，并返回 source/result 配对；Agent 按实际双图判断 |
| Skill 目录包含视频拆解，工具表没有视频观察 | 专业方法目录与当前注册能力分别展示 |
| 模型无后续工具调用即协议 completed | 主循环仍保持该语义；提示明确本轮结束不等于目标完成，Agent 根据成果回答 |

这些规则替换原 Prompt，不是向末尾追加开发任务。旧方法保留在共享目录；适配只作用于新版 Agent 模型视图。长方法的专业正文与参考分页保留。

## 未验证项与副作用

1. 本轮真实模型 A/B **未运行**，真实媒体调用为 0。实际数量遵从、主动保存文稿、合理澄清和事实判断仍需使用新会话做真实 query 验收，不能由 841 个离线测试代替。
2. 观察修订图会多带一张真实父图，视觉输入成本可能增加；父图缺失、模拟或地址不可用时，不能宣称完成保持验收。需要修复来源或说明限制。
3. 同次上传不一定属于同一商品，资料以 `co_upload_candidate` 明确标为候选；Agent/观察必须判断对应关系。来源身份保留不等于事实独立核验。
4. 聊天原稿存档会完整保留所选消息中的正文与说明，避免悄悄裁剪；Agent 必须选择正确消息。作品已是资产时应直接以其 ID 修订，不重复存档聊天展示副本。
5. 新稿是否保存、最终是否满足数量/事实约束仍由 Agent 决策。本轮没有增加自动强制保存全部回答、固定任务路由或额外总审查；其稳定性属于待真实模型验证项。
6. 旧会话已经保存的错误回答或膨胀工具结果不会被删除或追溯改写；新的记忆读取会避免继续放大回声。
7. 代码与验证记录通过当前修复分支交付；未部署。没有使用生产服务或模型额度。

## 回滚

变更分为 `A-prompts-and-methods.patch` 和 `B-memory-and-tools.patch`；A/B 是审阅分组，发布和回滚应作为一个整体处理，避免提示词与工具能力错配。测试与重放脚本另见 `validation.patch`。

保存后续改动后，可先对三个 patch 分别执行 `git apply --reverse --check <patch>`，检查通过再反向应用（先 validation、再 B、再 A）。不要清理用户原始数据或整个工作目录。也可以在独立 checkout 使用基线 `35547a2` 对照回退；本轮未迁移持久化格式，既有记录、批准和版本继续保留。

`sourceMessageId` 是 save_document 的明确新输入方式，省略 content 时必须绑定当前会话真实消息；不接受空请求或不存在的 ID。旧的 content/parentId 调用保持兼容。回滚到旧版后，已保存文稿仍保留正文、sourceIds 与父版本；新加的消息来源元数据可作为普通附加字段保存。
