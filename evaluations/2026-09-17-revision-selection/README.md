## 选材校验边界

素材的语义相关性、用户指代和选择范围由Agent判断。程序不按标题、措辞或业务猜测判定“选错”，也不自动把其他资料塞给观察模型。读取目录和原文后再选择仍是Agent职责。

引用校验保留存在、可访问、类型匹配；显式指定不存在的版本属于无效对象引用，但不再要求模型声明版本。用户隔离、工具Schema、准确片段能否应用、存档是否忠实复制原文、冻结媒体批准、幂等和预算属于执行完整性，继续保留，不是对选材语义的审查。

具体减少了五类原有要求：修订时强制重抄聊天原文、增量修改必填父版本、已选资产再用sourceText核对整份父稿、同批有文字但没选时阻止观察、来源登记的图片未进视觉参数时阻止准备方案。父资产始终由parentId指向的真实对象确定；sourceText只在选取聊天作品片段时使用。观察回执返回关联候选，媒体回执区分真正视觉输入与来源登记。遗漏必要素材应在真实任务验收中暴露，不新增语义阻断。

本轮按用户改变了上述职责，因此同步更新5处原先要求拒绝的测试断言，而非为了绿报表改业务结果。旧测试仍检查原文准确片段、错误版本、Schema、批准与真实输入；历史报告和原失败Trace原样保留。

## 真实对照设计与结果

现用`deepseek-flash`，reasoning=none。每次请求从空上下文开始，不含其他实验的回答；第二轮反转方法顺序。7种任务：价格、背景、同值不同产品、删句、两处不相邻修改、含CRLF的长文、指定段落改语气。原文和用户要求相同，输出方式分别是全文、before/after片段、段ID加改后段落。分段方式仅存在于评测器，不进入产品。

| 方法 | 简短提示词 | 强调最小变化的提示词 | 合计 | 实际total tokens |
| -- | -- | -- | -- | -- |
| 返回完整修改稿 | 14/14 | 12/14 | 26/28 | 13,453 |
| 返回准确片段替换 | 14/14 | 14/14 | 28/28 | 10,530 |
| 返回选定段落再拼接 | 14/14 | 14/14 | 28/28 | 11,725 |

表中是原始结果之上的人工语义复核，不能当生产成功率。三个接口Schema均28/28通过。最初精确文本/范围检查74/84；其中8项把“浅蓝色背景”与“浅蓝背景”判为不同，人工检查确认用户允许且其他字符完全未变，最终语义82/84。原expected与失败标记未改，修正判断单列在review.json。

另2项失败均为全文输出＋强调保持提示：用户要中段改成店员口吻，模型两次原样返回。没有缺原文、执行故障或ID问题，是模型未落实语气修改；不能据此宣称提示越长越稳定。

两种局部方案这批均通过，现有edits已支持把一整段作为before/after，同时保留其他段落。选择继续使用现有接口，避免新增分段ID、段落边界维护和拼接流程。tokens是这批实际用量，不是通用成本结论或现金费用。
