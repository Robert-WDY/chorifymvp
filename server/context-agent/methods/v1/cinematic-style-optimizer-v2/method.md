# 电影画面风格优化工作流

只优化可见的画面风格层。不得替用户改写剧情、镜头设计、演员表演、音频或生成参数。

## 1. 识别输入和目标

将任务归为：

- **原始剧本/场景**：输出可追加的全局风格块；除非用户明确要求，不自动拆分镜头或重写全文。
- **已有图片/视频提示词**：保持原结构，只清理、补充或替换风格表达。
- **纯风格需求**：推荐风格、解释差异或提供可直接追加的风格块。
- **图片/视频参考**：先理解可见内容，再匹配风格；用户只要分析或文字时不得擅自生成媒体。

明确用户要“推荐、优化、比较、查看示例”还是“实际生成/修改”。没有明确生成要求时只输出文字。

## 2. 建立内容锁

从原文提取并锁定：剧情事实、事件顺序、人物与动作、镜号/分段、时码、对白、构图、景别、运镜、音频、画幅和模型参数。用户提供完整提示词时保持原语言，除非用户要求翻译。

原始场景只要求风格块时，不补造摄影机、镜头、运镜、时长、画幅、年代或地点。多场景任务先定全局风格，再只对昼夜、内外景和明确情绪转折做局部变化。

## 3. 检索风格资料

- 选择风格时检索 `style-library.md`；使用 1 个主风格、0–2 个辅助特征和 1 套统一采集/色彩语言。
- 输入含摄影机、Log、ACES、胶片、LUT、球面/变形宽银幕等术语时检索 `technical-terms.md`。
- 需要改写范例或边界时检索 `examples.md`。
- 用户要求查看、解释或比较真实效果时检索 `style-image-examples.md`，再按索引读取对应的单个提示词样例或图片资产；不要一次载入全部 22 份样例。

示例只用于观察色温、色彩关系、对比、黑位、高光、颗粒和光学质感。不得把示例中的人物、公寓、雨夜、服装、构图或物件复制到用户内容。

## 4. 选择和消解冲突

按以下顺序选择：叙事情绪 → 真实光源与时间 → 肤色/主体可读性 → 跨镜连续性 → 用户已锁定审美 → 可观察性。

- 不把“电影感、8K、HDR、大片感、获奖摄影”当作风格证据。
- 不混用互斥的采集语言、球面/变形镜头或黑位要求。
- 颗粒、暗角、光晕、扩散和色差最多突出一项，其余保持轻微。
- 技术或品牌名称只写成“风格倾向/模拟”，除非用户明确提供真实拍摄设备。
- 用户明确要求混搭时保留创作意图，但说明这是风格模拟，不声称为真实摄影流程。

## 5. 优化文本

把风格块按以下顺序组织：

`成像/色彩倾向 → 色温与色彩关系 → 对比、黑位和高光 → 肤色/主体 → 光线质感 → 镜头/材质质感 → 克制后期效果`

使用可观察词语，避免术语堆叠。风格块通常控制在 40–100 个汉字或 35–80 个英文单词。已有提示词保持镜号、分段、时码和字段顺序，只改风格相关部分。

## 6. 校验结构保持

改写已有完整提示词时，可选外部诊断 `validate_style_preservation`：

- `originalText`：原提示词；
- `optimizedText`：优化后的完整提示词；
- `lockedLiterals`：必须逐字保留的对白、镜号、参数或用户指定原文；
- `checkTechnicalConflicts`：默认 `true`。

出现 `missingLockedLiterals`、`protectedTokenDifferences` 或 `conflicts` 时先修正再交付。脚本只做确定性核对，不替代风格审美判断。脚本不可用时只能说明“已人工自检”，不得声称已运行校验。

仅输出风格块、推荐或解释时无需运行脚本。

## 7. 输出

默认输出：

```markdown
### 风格诊断
- 输入类型：
- 叙事与情绪：
- 关键光线/色彩条件：
- 已锁定内容：
- 检出的冲突：无 / <具体冲突>

### 风格选择
- 主风格：`风格 ID / 名称`
- 辅助特征：
- 选择依据：

### 可追加风格块
<可直接追加的文本>

### 优化后的完整提示词
<仅已有提示词或用户明确要求完整提示词时输出>

### 冲突说明
<仅确有冲突时输出>
```

用户要求简洁时，只输出风格块和必要的完整提示词。默认只给一个主方案；用户要求比较时才给 2–3 个兼容候选。

## 8. creative 媒体工具边界

Agent按需要选择当前实际可用的资料读取或媒体工具，以真实回执作为依据。内置22风格仍是专业参考；仅实际提供的资料可声称已读。确有已绑定母版时复用并锁定主体、动作、场景、物件、机位和画幅，只替换风格块；没有时不能擅自多生成中性母版。

## 质量自检

- 风格选择能追溯到输入信号和风格库条目。
- 未改变任何锁定内容或原有字段结构。
- 全局风格统一，局部变化有明确叙事理由。
- 技术术语兼容并已翻译为可见结果。
