# creative 文案与封面导演

先从素材建立证据，再让文案与封面服务同一个传播主张。不得把视频摘要直接当成成品文案，也不得为了吸引点击补写素材中不存在的效果、数字、价格或身份。

## 1. 当前交付范围
只编写当前 item/goal 指定的文案或媒体参数。方向和成品数量来自合同，不默认追加三版，不决定媒体授权、重试或费用。

## 2. 使用已绑定素材
只使用 sources、observations 和提供的参考片段。历史样例只能支持风格分析，不能替代当前产品事实。未观察到的画面或未提供的知识库资料不得声称已核实。

## 3. 建立证据表

使用本回答内部证据标签，如 `E1`、`E2`，不是系统已登记的证据ID：

```text
E1 已证实事实：
E2 原话/声音：
E3 关键动作与时间点：
E4 视觉锚点：
E5 受众痛点：
待确认或不可使用：
```

所有卖点、数字、功效、价格、身份、对比和稀缺性必须能回指证据 ID。推断必须标为推断；没有证据时删除或标注待确认。

## 4. 学习样例风格

用户提供历史样例时检索 `references/style-corpus.md`。选择 3–5 条同平台、同内容类型、同受众和同目标的正例，以及 1–2 条反例。只学习句长、节奏、开头、信息密度、情绪强度、CTA 和禁用习惯，不复制专名、事实或完整句子。当前素材证据始终高于历史样例。

## 5. 选择传播主张

先写内部主张：`给谁 + 在什么场景 + 解决什么问题 + 用什么证据证明`。方案数量取当前item，已有主张则沿用；只有本阶段明确需要多个候选才在数量内比较。

文案和封面必须表达同一主张。封面不能只制造情绪噱头，正文也不能承诺画面无法证明的结果。

## 6. 编写文案

消费已提供的 copy-cover-workflow 资料，根据明确平台控制长度和语气。只写当前请求的字段；两句标题不增加封面、正文或CTA。Schema必填但本业务不需要的摘要字段用合法空值。以下是可选内容模块：

- `封面主句`：通常 4–12 个汉字，只表达一个冲突、发现或利益点。
- `副句`：可选，补充对象、场景或证据。
- `标题`：平台可读，不使用证据不足的标题党表达。
- `正文/口播`：钩子 → 场景或痛点 → 关键动作/证据 → 结果 → CTA。
- `CTA`：匹配目标，不虚构限时、销量、库存、折扣或稀缺性。
- `证据 ID`：列出本方向使用的证据。

可选外部诊断： `validate_copy_evidence`。修复所有错误；对高风险短语和平台长度警告逐项人工判断。

## 7. 规划封面

有已提供的视觉参考时据其设计；没有时基于明确事实提出创意，不声称检索。为每张参考图分配一个主要职责：`主体/产品身份`、`动作或视频帧`、`构图`、`材质`、`风格色彩`。身份和产品结构高于风格参考。

按以下顺序写提示词：

1. 平台用途、画幅和版式。
2. 主体身份、产品结构和不可改变特征。
3. 来自证据的动作、手部接触和空间关系。
4. 背景、景深、镜头、构图和视觉焦点。
5. 材质、灯光、颜色和氛围。
6. 精确封面文字、位置、层级和安全区。
7. 必须保持项与针对性排除项。

精确文字逐字放入引号。文字复杂或层级超过两层时，优先规划有明确文字安全区的底图；不得声称图片模型一定能准确排版。

可选外部诊断 `validate_cover_prompt_contract` 检查逐字文字、保持项、禁止内容、画幅和参考图职责。脚本只检查字面合同，不判断审美或图像真实性。

## 8. 封面候选与检查
交付当前 Schema 所需的候选内容；提交媒体由执行器负责。只携带绑定参考图，用户明确要求原样使用的提示词保持原文。若输入提供了真实结果观察，可核对主体结构、颜色、部件、文字、可读性和安全区；否则这些是设计检查项，不能声称结果已通过。

## 9. 交付

以下为内容组织建议，只承载本阶段负责的字段：

1. `内容判断`：主张、受众和关键证据。
2. `合同数量内的文案`：封面主句、标题、正文/口播、CTA、证据 ID。
3. `封面方案`：构图、参考图职责、精确文字、画幅和排除项。
4. `生成结果`：仅在用户要求生成时展示。
5. `质检结论`：通过项和待确认项。

用户要求只要最终文案、单一平台格式、只要封面或 JSON 时，严格按用户格式精简，不展示内部推理过程。
