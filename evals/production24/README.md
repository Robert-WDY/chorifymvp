## 数据修订

`source-cases.json` 原样保存附件场景数据。`cases.mjs` 是修订后的 24 个主场景和 4 个明确标注的变体。
原始附件的 Python 占位程序未执行。此处独立实现 runner、隔离 worker、评分器和负例测试。

- C001 允许必要澄清或合理假设下的概念视频；没有产品图片不一概判错。
- C002 保留 15 秒限制作为能力边界，新增 5 秒参考图正例。
- C003 补充具体产品和时长，检查确认前零提交、确认后使用冻结参数。
- C004、C005 先运行真实模型生成模拟草稿，再恢复/编辑；保留完整第一轮 trace。C004 的内容拒绝由明确的 Fixture 注入，不冒充视觉评审。
- C006、C007 提供视频引用；当前执行器未开放视频分析，明确列为能力缺口。
- C008 保留 20 个文件目标并要求完整交付，新增 10 条对照。首轮曾误设为整任务能力缺口；追踪发现原限制仅是单批12，修订后统一支持单批20，原始目标Schema允许更大数值并由执行器明确处理超限。
- C009 修正错误标签：没有图片也能提供文字方向。
- C010 提供品牌事实和参考图；C011–C017 补齐媒介或产品事实，避免评测者擅自把“广告”解释为视频。
- C018 拆成明确拒绝、提交回执丢失、查询超时三种注入。
- C019 实际经历缺原图和补原图两轮，检查任务身份和素材传递。
- C020 在 SessionStore 持久化 providerTaskId 后强制结束 Node 子进程，再启动新进程加载磁盘状态和模拟服务回执。检查 PID 改变、任务及回执不变、只提交一次。
- C021 首轮建立待确认视频方案，第二轮改变为图片。
- C022 使用具体非法请求，检查拒绝且不提交媒体。
- C023 检查独立交付项，不要求某种线程调度顺序。
- C024 检查依赖完成在前、脚本内容进入媒体 Skill 输入。

## 边界

模型是实际配置的豆包，理解、规划、文字和计划验证均实际调用。媒体提供方是确定性模拟器，fixtures.invalid 地址不对应真实图片或视频。模拟媒体只验证执行合同、参数传递、状态、版本和恢复，不评估视觉质量、网络可访问性、视频内容或真实供应商能力。没有把模拟产物计为真实产物。

每项保存 query、全部模型请求/响应、状态、工具记录、供应商提交、逐轮快照及评分。期望结果只用于评分，未放入模型输入。每轮冻结 server、skills 和本评测程序的源码并核对 hash。输出分类区分流程完成、正确安全停止、能力缺口正确处理、能力缺口处理错误。评测不只检查最终话术，也不以“给出解释”替代交付成功。
